### Stage: Core Technical Assessment

#### Q2. What is the difference between SQL and NoSQL databases?
- **Difficulty**: `Medium` | **Time Budget**: `10 mins` | **Match**: `42.7%`
- **Category**: Technical | **Tagged Skills**: SQL & Databases, System Design

**Ideal Answer Outline:**
> SQL databases are relational, use structured schemas, and support ACID transactions (e.g., PostgreSQL, MySQL). NoSQL databases are non-relational, schema-flexible, and optimized for horizontal scaling (e.g., MongoDB, Cassandra). The choice depends on data structure, scalability needs, and consistency requirements.

**Follow-Up Probing Questions:**
- [ ] How would you handle single points of failure and database partition tolerance?
- [ ] What caching eviction strategy (LRU/LFU) would you implement and why?
- [ ] How would you estimate read vs write throughput and storage capacity for 5 years?

**Evaluation Signals (What to look for):**
- [x] Clearly identifies bottleneck components (Load Balancer, Caching layer, Database).
- [x] Applies horizontal vs vertical scaling concepts appropriately.
- [x] Considers latency, consistency trade-offs, and fault-tolerance.

**Red Flags (Watch out for):**
- ⚠️ Proposes a single central database with no indexing or caching strategy.
- ⚠️ Cannot articulate difference between horizontal and vertical scaling.

### Stage: System Architecture & Problem Solving

#### Q3. What is the difference between a process and a thread?
- **Difficulty**: `Medium` | **Time Budget**: `10 mins` | **Match**: `36.2%`
- **Category**: Technical | **Tagged Skills**: Concurrency & OS

**Ideal Answer Outline:**
> A process is an independent program with its own memory space, while a thread is a lightweight unit of execution within a process that shares the process's memory. Threads are faster to create and switch between, but require careful synchronization to avoid race conditions.

**Follow-Up Probing Questions:**
- [ ] How do mutexes, semaphores, and spinlocks differ in overhead and usage?
- [ ] Can you describe the 4 Coffman conditions required for a deadlock to occur?
- [ ] How does the OS scheduler manage context switching between user-level and kernel threads?

**Evaluation Signals (What to look for):**
- [x] Demonstrates precise grasp of shared memory, race conditions, and synchronization primitives.
- [x] Articulates real-world deadlock prevention techniques.

**Red Flags (Watch out for):**
- ⚠️ Confuses thread-safe memory sharing with independent process isolation.
- ⚠️ Unaware of race condition risks in concurrent environments.
